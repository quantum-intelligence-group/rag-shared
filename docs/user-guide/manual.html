1. What rag-shared is

rag-shared is a Python library, not a running service. It packages three utilities that the Python services of the Nexus RAG pipeline import so that they log, trace and cache in the same way:

  • Readable logging (rag_shared.logging): a "Milvus-style" bracket log format written to stdout.
  • OpenTelemetry observability (rag_shared.observability): one-call tracing setup with OTLP export, plus a JSON operational-event emitter that the log relay forwards to Loki.
  • Dragonfly/Redis cache client (rag_shared.dragonfly): a small pickle-based key/value client used to pass payloads between workflow stages.

The package is named rag-shared, version 2.0.0 (from pyproject.toml and __version__), requires Python 3.10 or newer and is built with hatchling from src/rag_shared.

Where it sits: in this group of repositories, rag-developer, rag-download, rag-embed-index, rag-metadata and rag-milvus-index list it in their requirements.txt. The Rust services (for example rag-chunking) do not use it; they carry their own observability.rs.

2. Installing

The README gives the install commands. The package is installed straight from GitHub:

# Basic (logging + dragonfly client)
pip install git+https://github.com/quantum-intelligence-group/rag-shared.git

# With OpenTelemetry observability
pip install "rag-shared[observability] @ git+https://github.com/quantum-intelligence-group/rag-shared.git"

3. Logging

Setup

from rag_shared import setup_logging, get_logger, timed

setup_logging()              # once at startup; level from LOG_LEVEL, default INFO
logger = get_logger(__name__)
logger.info("Chunk created", extra={"chunk_id": "abc", "size": 1024})

setup_logging(level=None) clears every handler on the root logger, installs one StreamHandler on sys.stdout with MilvusFormatter, and sets urllib3, httpx, httpcore, asyncio and opentelemetry to WARNING. An unknown level name falls back to INFO.

Log line format

[timestamp] [LEVEL] [module:line] ["message"] [key=value] ...
[2025/12/31 18:42:23.765 +00:00] [INFO] [main:15] ["Chunk created"] [chunk_id=abc] [size=1024]

Timestamps are always UTC. Context fields come first, then any extra= fields, then [exception=Type: message] when exc_info is set. Values are rendered by _format_value: None becomes null, booleans are lower case, strings with spaces are quoted, and non-integer floats are rounded to two decimals.

Timing and request context

FunctionBehaviour
timed(operation, logger=None, **extra)Context manager. On success logs "<operation> completed" with duration_ms; on an exception logs "<operation> failed" at ERROR with duration_ms and error, then re-raises. It yields a dict you can add fields to.
log_context(**fields)Adds fields to every log line inside the block, using a ContextVar, so it is safe across asyncio tasks.
clear_log_context()Empties the current context.

Deprecated names that still work

For code written against v1.x: configure_logging(...) calls setup_logging and ignores service_name, service_version, environment and json_output; stage is timed; RequestContext wraps log_context; add_context, clear_context and request_context are kept; StructuredJSONFormatter is now an alias of MilvusFormatter, so it no longer produces JSON.

4. Tracing and operational events

from fastapi import FastAPI
from rag_shared import setup_observability

app = FastAPI()
logger = setup_observability("my-service", app)

setup_observability(service_name, app=None, instrument_http=True) does the following, in order:

  1. Sets SERVICE_NAME in the environment if it is not already set.
  2. Creates a TracerProvider with an OTLP gRPC exporter (insecure) pointed at OTLP_ENDPOINT, with resource attribute service.namespace=rag-orchestration. Skipped when TRACING_ENABLED is not true.
  3. Calls setup_logging and, when tracing is on, the OpenTelemetry logging instrumentor for trace correlation. Skipped when STRUCTURED_LOGGING_ENABLED is not true.
  4. Instruments the requests and httpx clients.
  5. For a FastAPI or Starlette app: instruments it (excluding /health, /healthz, /ready, /metrics, /docs, /openapi.json) and wires the "observability floor" described below. For a Flask app: instruments it only.
  6. Emits a service_start JSON event and returns a logger.

The observability floor (FastAPI only)

The readable bracket logs are dropped by the log relay, which parses each stdout line as JSON. So emit_event(event, level="info", **fields) writes a single JSON line with event, level, service and any non-null fields. For FastAPI apps the floor adds:

  • An HTTP middleware that emits handler_entry and then one of handler_success, handler_validation_error (4xx), handler_not_found (404), handler_conflict (409) or handler_error (5xx), with method, path, status_code, duration_ms and the x-request-id header. Health, readiness, metrics and docs paths are skipped.
  • service_ready at startup and service_shutdown at shutdown, by wrapping the app's existing lifespan.
  • A heartbeat event every 60 seconds carrying service_version (from SERVICE_VERSION, or unknown).
The code comment on emit_event says the event name must be an allow-listed name (handler_*, service_*, dependency_*, stage_*, job_*, heartbeat) and that only counts and ids may be passed, never content. The library does not enforce either rule; it is on the caller.

5. Dragonfly cache client

from rag_shared import get_dragonfly_client

cache = get_dragonfly_client()          # shared singleton by default
cache.store("my-key", {"data": [1, 2, 3]}, ttl=3600)
data = cache.retrieve("my-key")

DragonflyClient connects lazily on first use (redis-py, decode_responses=False, 5 second socket and connect timeouts, retry on timeout, db 0). Values are serialised with pickle, so any Python object can be stored.

MethodReturns
ping()True, or False on a connection error.
store(key, data, ttl=None)True on success. Uses SETEX with the default TTL when none is given.
retrieve(key)The unpickled object, or None if absent or on error.
delete(key), exists(key)Booleans.
get_ttl(key)Seconds, -1 for no expiry, -2 if missing, None on error.
set_ttl(key, ttl)Boolean.
keys(pattern="*")List of key names (uses Redis KEYS).
close()Closes the connection; the client is also a context manager.

Every method catches its own exceptions, logs them at ERROR and returns a falsy value. A cache outage therefore shows up as None/False results plus Failed to ... log lines, not as an exception.

Because values are pickled, only read keys written by trusted services: unpickling untrusted data can execute code. keys() uses KEYS, which scans the whole keyspace and should not be called in a hot path.

7. Development and tests

Tests live in tests/test_logging.py and cover the formatter, timed, log_context and the backward-compatible names. With the dev extra installed, run them with pytest. Formatting and lint settings are in pyproject.toml (black and ruff at line length 100, mypy for Python 3.10). There are no tests for the cache client or the observability module in the repository.

8. Troubleshooting and limits

  • "Warning: OpenTelemetry not installed" printed at startup: install the observability extra, or set TRACING_ENABLED=false to silence it.
  • Logs from a service do not reach Loki: only the JSON lines from emit_event are relay-forwardable. Bracket-format log lines are, per the code comment, dropped by the relay.
  • Handler events missing for a Flask app: the observability floor is wired only for FastAPI and Starlette apps.
  • Another library's log handlers vanish: setup_logging clears all root handlers by design.
  • Cache returns None unexpectedly: look for Failed to retrieve data or Dragonfly ping failed in the logs and check DRAGONFLY_HOST/DRAGONFLY_PORT.

There is no Dockerfile, compose file or HTTP interface in this repository; it is consumed only as a pip dependency.

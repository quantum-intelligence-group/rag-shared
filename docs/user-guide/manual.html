RAG Shared: User Manual

Classification: QIG Confidential. Audience: engineers who build or maintain the Python services of the AI Navigator (RAG) pipeline.

1. What rag-shared does

rag-shared is a small Python library, not a running service. It holds the code that several AI Navigator services need in common, so each one does not carry its own copy: a structured logger, a request-context helper, an optional OpenTelemetry setup for FastAPI services, and a client for the Dragonfly cache (Redis-compatible). Nothing runs on its own; a service installs the package and calls it.

2. What it provides

PartWhat it gives you
Loggingsetup_logging, get_logger, timed and log_context. Log lines use a bracketed format: timestamp, level, module and line, the message, then any key=value fields. timed logs how long a step took. log_context adds fields such as a request id to every log line inside a block.
Observabilitysetup_observability(service_name, app) wires tracing and structured logging into a FastAPI application. It needs the observability extra.
Cache clientget_dragonfly_client() returns a client with store and retrieve for Python objects, with a time-to-live.
Older namesconfigure_logging and stage from version 1 still work.

3. Installing and using it

pip install git+https://github.com/quantum-intelligence-group/rag-shared.git
# with OpenTelemetry support:
pip install "rag-shared[observability] @ git+https://github.com/quantum-intelligence-group/rag-shared.git"
from rag_shared import setup_logging, get_logger, timed, log_context

setup_logging()                 # once, at start-up
logger = get_logger(__name__)
with log_context(request_id="req-123"):
    with timed("embed_chunks", logger):
        logger.info("Processing started")

Python 3.10 or later is required. The extras are observability, flask and database; all installs them together. To work on the library itself, install it in editable mode and run the tests in tests/.

The variables belong to the service that imports the library, so set them in that service's environment.

5. Troubleshooting

SymptomWhat to check
No traces appearCheck that the observability extra is installed, TRACING_ENABLED is true and OTLP_ENDPOINT is reachable from the service.
Cache calls failCheck DRAGONFLY_HOST and DRAGONFLY_PORT from inside the service's container.
Log lines are missing a request idThe code is outside the log_context block.
An import fails after an upgradeVersion 2 keeps the version 1 names; check the installed version and the extras.

6. Getting help

Raise a ticket for the AI Navigator project in Pulse, naming the service (rag-shared), the request or document involved and the time of the failure. Do not attach customer documents, credentials or tokens.

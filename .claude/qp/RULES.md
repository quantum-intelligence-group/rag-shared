# Quantum Pack — Discipline Rules

Numbered rules the Pack enforces. Severity: **HardBlock** (blocks the action),
**Warn** (advises, does not block), **Info** (guidance). The visualize gate's severity is
set by the configured enforcement level (`off` → Info, `warn` → Warn, `block` → HardBlock).

| ID | Rule | Severity |
|----|------|----------|
| **QP-R1** | **Arrange, don't invent.** The Pack composes native CLI primitives; it adds no new machinery. A capability that needs a feature the CLI lacks is out of scope. | Info |
| **QP-R2** | **Classify before work.** Every idea is typed — `build` / `enhancement` / `action` — before any stage acts on it. | Warn |
| **QP-R3** | **No build before an Agreed spec bundle.** Build/create actions are gated until a spec bundle for the active idea reaches `status: Agreed`. | per enforcement level |
| **QP-R4** | **Create = consume → plan → build → emit.** The Agreed bundle drives the build; the built outcome is emitted onto the thread. The builder is the CLI itself (Claude-native); the maker-platform service is an optional bridge. | Warn |
| **QP-R5** | **One append-only OutcomeThread per idea.** Every stage links to it by **reference, not copy**. The thread is never rewritten, only appended. | Warn |
| **QP-R6** | **Tier + gate assets; protect by license *and* control.** Commodity ships plaintext; the crown-jewel role-model/corpus is **gated — pulled at runtime from a private repo, never persisted** in the customer repo. Distribution is gated (private licensed repo + GitHub App, revocable, audited) and **watermarked per licensee** for leak attribution. | Warn |
| **QP-R7** | **Substrate seam.** The Pack never hard-depends on a backend. Substrate (crypto, multi-user state, external systems) is reached through a bridge that lights up when present and degrades gracefully when absent. | Warn |
| **QP-R8** | **Token frugality (no token shock).** Minimize tokens: discipline detail lives in on-demand skills, not always-on context (one-line pointer only, kept **small and stable** for prompt-cache hits); hooks are silent on success; artifacts stay lean and read **partially** (latest N thread events, roll up old ones); fetch with `gh --json <minimal fields>`, never raw dumps; model/effort right-sized per stage; subagents only when a large read returns a small summary; expensive operator tools are not auto-invoked (`disable-model-invocation`). | Warn |
| **QP-R9** | **Claude + GitHub only (V1).** Keep everything in the Claude CLI and GitHub — no other servers, DBs, or sign-ups. Claude reasons; GitHub is the system of record. Other substrate is a post-V1 bridge. | Warn |
| **QP-R10** | **Self-extension stays local.** Capabilities authored via QP use their own namespace (never `/qp-`), are traced outcomes (QP-R5) subject to the gate + IP rules, and **stay local** — never auto-shared. Sharing happens only by routing the extension as an idea to the customer's QOS maker (a QOS-version bridge). | Warn |
| **QP-R11** | **Recognize & coexist.** On activation, QP detects Maker and QOS scaffolding and adapts — never duplicating or colliding: defer the commit-gate to Maker's pre-commit when present; route sharing to the QOS maker when QOS present (D12). Readiness scans are **multi-fingerprint** (Maker/QP/QOS), never single-product. | Warn |
| **QP-R12** | **External systems are read-only by default.** Treat the user's real GitHub org (and any external system) as read-only. Any outward-facing change — branch / commit / PR / merge — requires describing the exact change and getting **per-action confirmation** first. Never automatic, never auto-merge. | HardBlock |
| **QP-R13** | **Cost-aware model routing.** Right-size the model per task: mechanical/deterministic stages (status, coverage, classify, portal) run on the cheapest sufficient model; high-value reasoning (visualize, build) keeps a capable model. Prefer mechanical tool execution (`gh`, scripts) over model reasoning — token reduction first (no quality tradeoff), model right-sizing second (tune carefully). **No separate installs:** these in-CLI levers are the whole QP cost strategy; gateway-based local routing stays internal to maker-ops/QOS, never required of a QP customer. | Warn |
| **QP-R14** | **Correctness is the proof point.** Beyond these QP-specific rules, QP adopts a full **generalized correctness/safety standard** — the Maker ruleset rewritten stack-agnostic. **Load `GOVERNANCE.md` on demand** when governing a build or commit (QP-R8 — never always-on). Its `[GATE]` rules are hard-blocked by `qp-gate.sh`; the rest are agent-followed. Nothing is marked **done** until its acceptance criteria are verified against the implementation (ran-vs-wrote; no stub counts). Full runtime evaluation of the standard is the `mvp-governance` engine — the paid Maker/QOS layer. | per enforcement level |
| **QP-R15** | **Human voice — no AI tells.** Every document the Pack authors or edits as first-party prose (specs, portals, READMEs, customer-facing collateral) gets a human-voice pass that strips machine-generation tells: no em dashes at all (replace each with a comma, colon, parentheses, or a separate sentence, and fix the surrounding grammar and punctuation), the "not X, Y" antithesis, forced triads, inflated vocabulary (delve / leverage / robust / seamless / underscore / tapestry / realm / foster / unlock…), hedging filler and promotional closers, formulaic section scaffolding, and emoji in formal docs. Vary sentence structure, use plain words, follow the QIG voice. **Exempt (operator directive 2026-07-18):** content we did not author as first-party prose — ingested or imported material, third-party or vendored files, auto-generated output (fix the generator, not the file), test fixtures and sample data, and machine-generated state logs. Verbatim brand strings (tagline, classification footers) are also exempt. Mirrors QOS R-23.7. | Warn |
| **QP-R16** | **Instructions at a 10th-grade reading level — and NO fabricated specifics.** Every instruction a person follows — runbooks, remediation steps, guides, decision-card explainers, prompts/errors, any step-by-step — reads at a 10th-grade level: short sentences (≤ ~20 words), plain words, one action per step, where + how-to-verify, imperative; never developer-only. **HARD (no fabrication — QP-R1/correctness, mirrors R-1.1/R-1.2):** every concrete path / command / file / container / host / URL / env-var / label / identifier MUST be verified to exist before it is written; if it can't be verified, the step says "find / confirm X", never an invented literal (state the uncertainty). Mirrors QOS R-23.8. | Warn (reading level) / **HardBlock (fabrication)** |

## Enforcement levels

Configured in `quantum-pack.json` (`enforcement.default`) and overridable per project:

- `off` — rules are advisory (Info only).
- `warn` — violations are reported, work proceeds. **Shipped default.**
- `block` — QP-R3 becomes a HardBlock: build actions are refused until the bundle is Agreed.
  **Incubation runs here.**
